# 잔차 반올림 흡수와 정확한 문맥 상태 전이 — 2026-09-07

## 1. 어떤 핵심을 바꿨나

이전에는 필요한 중간값을 싸게 생성하려다 원본 가중치 전체를 다시 읽었다. 이번에는 **중간값을 어떤 값으로 계산하더라도 관측 결과가 같다는 관계**를 생성한다. 그 관계가 성립하면 중간값을 재구성하지 않고 관련 행렬 자체를 질의 경로에서 제외한다.

선택한 연산은 실제 Transformer에 있는 잔차 덧셈이다. 참조 ABI를

    R(x,b) = RN_BF16(RN_FP32(x+b))

로 고정한다. 원래 체크포인트의 계수들을 수정하지 않고, 분기의 모든 가능한 결과가 `[-B,B]` 안에 있음을 보장하는 메타데이터를 생성한다. 입력의 양 끝 평가가

    R(x_i,-B) = R(x_i,+B) = x_i

를 모든 좌표에서 만족하면, 단조성 때문에 실제 분기값을 계산하지 않아도 `R(x,b)=x`가 성립한다. `±0`, 비유한 값, 오버플로 가능성은 보수적으로 거부한다. 조건을 충족하지 않는 노드는 원본을 한 번 실행한다. 근사값을 만든 뒤 원본으로 재실행하지 않는다. 그 정상 경로를 가속 성공으로 세지 않는다.

이는 알려진 부동소수점 흡수, 구간 해석, 죽은 계산 제거를 이용한 구성이다. 그 분야나 반올림 현상을 새로 발명했다고 주장하지 않는다. 이번에 연결한 것은 원본 행렬의 경계 생성→질의 전 분기 제외→살아 있는 KV 기록→전체 문맥에 대한 유한 전이 생성이다.

## 2. 비교한 세 원리와 선택 근거

A는 값 생성 대신 관측상 동일한 잔차 전이를 증명한다. 분기가 모두 없어져도 KV와 최종 head를 남기는 실제 일정의 projection 비율을 계산할 수 있어 제한된 10배 경로가 있다. 통과율과 준비 비용이 미해결 조건이다.

B는 난수를 먼저 관측 조건에 넣어 전체 로그잇 대신 동일 경로의 샘플을 만드는 방향이다. 같은 분포는 같은 RNG 경로가 아니므로 단순 샘플러 교체는 허용하지 않았다. 최종 head만 무료로 없애도 아래 구성의 projection 약 99.48%가 남는다. 이를 단독 핵심으로 만들지 않았다.

C는 여러 잔차 기록을 합쳐 실수에서 상쇄되는 부분을 지우는 방향이다. `x=1,c=1/256`일 때 BF16 중간 저장을 둔 `R(R(x,c),-c)`는 `0.99609375`다. 실수의 증분 합은 0인데 원본은 identity가 아니다. 두 단계 native 전이 관계를 따로 구성하지 않은 채 식을 합치지 않았다.

세 개의 범용 유효 원리를 확보했다는 뜻은 아니다. A의 살아 있는 조건부 연결에 집중했으며, 시드·규모를 늘리는 것으로 핵심 검증을 대신하지 않았다. 최초 사전등록과 후속 문맥 몫 구성은 첫 실험 실행 전에 고정했다.

## 3. 가중치를 읽지 않는 경계를 어떻게 만드나

원본 BF16 행렬 W의 각 행 절댓값 합을 정확한 유리수로 더한다. 그 최댓값을 위쪽의 2의 거듭제곱 L로 저장한다. n은 입력 폭, r은 현재 정규화된 입력의 실제 최대 절댓값이다. `u=2^-24`, `η32=2^-149`, `η16=2^-133`로 둔다.

선언한 순차 FP32 곱·합, `n<=2^20`과 유한 범위에서는

    |FP32_dot| <= 2 r L + 4 n η32
    |BF16_store(FP32_dot)| <= 4 r L + 8 n η32 + η16.

곱의 반올림과 각 덧셈의 오차를 모두 포함한다. `(1+u)^(n+1)<2`와 점진적 언더플로의 절대 오차를 사용했다. 코드에서는 마지막 우변을 다시 위쪽 2의 거듭제곱으로 올린다. 이 상계가 `2^120`을 넘으면 인증하지 않는다. 모든 중간 곱·합이 FP32 범위를 벗어나지 않는다는 충분조건도 이 제한에 포함된다.

SwiGLU에는 gate와 up의 위 경계를 적용하고, SiLU의 `|out|<=2|in|` 범위, 곱의 반올림, down projection 경계를 순서대로 적용한다. 경계 계산에 G/U/D 배열은 필요하지 않다. 각 행렬의 폭과 한 개의 보수적 합 경계만 읽는다. 정규화 입력 자체는 원본 연산으로 계산하며 그 비용은 남는다.

SiLU는 CPU PyTorch 2.10.0의 BF16 입출력 65,280개를 저장한 128KiB 표로 참조 의미를 고정했다. 모든 유한 입력에서 범위를 검사했고 위반은 없었다. 실행기 초기화도 이 표와 범위를 검증한다. 이는 단항 수치 ABI의 유한 표이지, 모델의 모든 입력 조합을 열거한 응답표가 아니다. 생성·검사 비용은 따로 지불한다. 다른 GPU 함수 구현과의 동일성을 주장하지 않는다.

Attention에서는 Q의 경계와 캐시 K의 최대값으로 점수가 유한함을 보장한다. 안정화된 지수함수에 `0<=exp(s)<=1 (s<=0), exp(0)=1`이라는 명시적 기본 연산 계약을 둔다. 비음수 FP32 분모는 각 항 이상이며, 확률을 BF16에 저장해도 각 항은 `[0,1]`이다. 따라서 T개의 value 합에 `T*max|V|`를 넣어 같은 곱·합 오차 경계를 적용할 수 있다. 출력 projection 경계까지 현재 잔차 셀 안에 들어가면 Q/score/softmax/AV/O를 생략한다.

**증명 신뢰 범위:** 행렬·반올림 관계는 유도된 충분조건이고, 정확한 수치 경계는 Fraction으로 계산한다. 완전한 proof-assistant 검증은 아니다. NumPy exp의 위 범위 계약은 구현/ABI 가정이며, 실행한 원본 attention에서는 매번 검사했다. 생략한 모든 가상 경로의 NumPy exp를 전수 검사한 것은 아니다. SiLU 범위는 유한 전수 검사로 별도 고정했다. 수치 검증기는 실수 연산만 다루면 충분하지 않다는 선행연구와 이 구분을 유지했다.

## 4. 현재 출력이 같아도 KV를 삭제하면 안 된다

Attention 출력이 잔차에서 없어져도 현재 토큰의 K/V는 미래 어텐션에서 사용될 수 있다. 첫 실행기는 K/V projection과 기록을 그대로 수행하고, 그 밖의 attention 계산만 인증 후 생략한다. 최대값 메타데이터는 새 K/V를 기록할 때 갱신하며 과거 캐시 전체를 훑어 만들지 않는다.

현재 잔차가 65536이고 추가되는 값이 1이면 BF16 결과는 그대로다. 하지만 V=1을 기록한 다음 V=0과 함께 평균하는 후속 질문의 값은 0.5다. 첫 V를 삭제하면 0이다. 이런 작은 상태 반례를 검사에 포함했다. 중간 출력이 같다는 이유로 살아 있는 기록을 없애지 않았다.

원본과 실행기의 KV가 같고 현재 입력도 같다고 가정한다. 정규화·새 K/V는 같은 원본 수치 연산으로 생성한다. 인증된 잔차는 정확히 identity이며, 나머지 잔차는 원본 노드를 한 번 실행한다. 따라서 다음 층 입력과 갱신된 KV가 같다. 이를 층과 토큰 시간에 대해 귀납하면 로그잇과 KV가 같아지고, 동일한 샘플러를 각자의 같은 로그잇·RNG 상태에 적용하므로 토큰과 RNG도 같다.

## 5. 후속 발견: 전역 인증이면 문맥 이력을 열거하지 않는 표가 가능하다

각 원본 토큰 임베딩 E[t]에 대해 모든 층과 최대 문맥 길이 T_max의 경계를 검사한다. **모든 토큰·모든 층의 잔차가 identity라고 인증되면** 다음이 귀납적으로 성립한다.

    모든 층의 잔차 입력 = E[현재 토큰]
    K_l(t) = 原本 K_l_projection(原本 norm_l(E[t]))
    V_l(t) = 原本 V_l_projection(原本 norm_l(E[t]))
    logits(t) = 原本 head(原本 finalnorm(E[t]))

이 조건 아래에서는 이전 연구에서 실패한 ‘두 번째 층 이후도 토큰만으로 정해진다’는 연결이 실제로 증명된다. 토큰 결정성만 가정한 것이 아니라, 문맥의 영향을 전달할 잔차 쓰기가 전부 흡수된다는 충분조건에서 나오는 결과다.

생성기는 어휘 V개에 대한 K/V와 원본 로그잇을 만든다. `V^T`개의 문맥을 실행하거나 `Q^h`개의 숫자 입력을 열거하지 않는다. 실행기는 현재 토큰으로 정확한 행 주소를 계산하고, K/V 행을 **그대로 실제 캐시에 추가**하며, 원본 로그잇 행을 반환한다. 자체 RNG를 같은 방식으로 갱신한다. 원본 행렬 경로나 비선형 함수가 이 표 실행기의 인자가 아니다. 원본 체크포인트 없이 표만 복사한 새 디렉터리에서도 검사했다.

이것은 조건부 완전 참조 전이다. **전역 조건을 만족한 모델은 그 허용 문맥에서 이미 로그잇이 과거 문맥에 의존하지 않는 모델이다.** 이런 유리한 모델을 일반적인 지능형 405B로 바꿔 말하면 안 된다. 학습된 일반 모델의 문맥 처리를 공짜로 삭제하는 결과가 아니다.

## 6. 고정 실험과 실제 결과

두 시드71/109, h32, f96, 4 query heads, 1 KV head, head_dim8, 4층, 어휘32의 제로 없는 무작위 조밀 BF16 가중치를 사용했다. 임베딩은 절댓값 `[1,2)`에 무작위 부호를 준 후 `2^s`, s=0/16/32/48의 별도 합성 체크포인트로 생성했다. 높은 크기의 집단은 **의도적인 양성 대조군**이다. 실제 체크포인트를 변형한 뒤 원본이라고 부르지 않았으며, 생성 후 원본 파일 해시가 모두 유지됨을 확인했다.

참조 모델은 순차 FP32 projection, BF16 저장, RMSNorm, GQA causal attention, SwiGLU, 최종 head를 가진다. **RoPE가 없고 HF/실제 CUDA의 ABI가 아니다.** 공개 사전학습 모델을 실행한 것이 아니다. 전역 증명 문맥 한도는32, 실측 시퀀스 길이는16, 체크포인트마다2개 독립 시퀀스다.

| 임베딩 크기 | 모델 수 | 직접 실행에서 잔차 identity (attention/MLP) | 경계로 생략 (attention/MLP) | 전역 표 생성 |
|---|---:|---:|---:|---:|
| 2^0 | 2 | 0/0 | 0/0 | 0/2 |
| 2^16 | 2 | 256/256 | 0/0 | 0/2 |
| 2^32 | 2 | 256/256 | 256/256 | 2/2 |
| 2^48 | 2 | 256/256 | 256/256 | 2/2 |

보통 크기 집단에서는 이 메커니즘으로 제거할 잔차가 관측되지 않았다. 2^16 집단에서는 실제 결과는 같지만 보수적인 경계가 넓어 인증하지 못했다. 이 두 종류의 실패를 구분했다.

256단계·8,192개 로그잇 좌표에서 원본과 guarded 실행이 일치했다. 표를 만든 네 모델의128단계·4,096개 로그잇 좌표도 원본과 같았다. 각 실행은 자신의 로그잇과 RNG로 다음 토큰을 선택했다. 로그잇만이 아니라 매 단계 전체 KV 해시와 마지막의 **실제 KV 비트 배열**도 대조했다. 새 토큰 미래 답을 원본에서 전달한 검사가 아니다.

표가 없는 집단의 guarded 경로는 원본 projection을 전부 수행했다. 따라서 0 mismatches는 모든 입력에서 가속했다는 뜻이 아니다.

## 7. 정확히 무엇을 읽고 계산했나

양성 대조군의 원본 체크포인트는98,880바이트다. 정상 한 토큰에서 직접 읽는 원본 데이터는96,896바이트다.

- guarded 단계는 projection MAC의6.383%, 원본 데이터 읽기의7.001%가 남았다. KV와 head를 실제로 계산했다. 정규화·메타데이터·경계·캐시·샘플러 비용은 별도다.
- 전역 표는8192바이트다: KV4096, logits2048, 보존 임베딩2048. 실행 시 행렬 곱은 없으며, 매 토큰 **표에서192바이트를 실제 읽었다**. 표 전체를 매 질의 읽지 않았다.
- 실행 초기화 때 표8192바이트와 runtime JSON을 읽어 해시를 검증했다. 준비 단계에서는 원본 전체 스캔과 상태/로그잇 표 생성을 지불했다. 32개 토큰 표 생성의 projection MAC은98,304회, 이때 소스 데이터 읽기는206,848바이트였다.

192/96896≈0.198%는 **표 질의 읽기와 원본 소스 읽기를 비교한 수치**다. 500배 실행 가속이나 실제 GPU 트래픽이 아니다. 코드와 데이터 이동·디코드·cache copy·샘플링은 계속 존재한다.

중요한 구현 구분: 값은 BF16이지만 NumPy 실행 배열은FP32다. 새 KV64개를 저장할 때 실제 원시 배열은256바이트이며 BF16 payload128바이트와 다르다. Python 리스트·객체 헤더·할당자 비용도 남는다. 32단계 KV 실제 배열은8192바이트, BF16 직렬화는4096바이트다. 최대 RSS/GPU 총 할당은 측정하지 않았다.

준비의 최소 소스/쓰기, activation·metadata 읽기, 표 시작 검증, 표 질의, FP32 캐시 기록과 출력 배열 쓰기를 더해도, 준비+32토큰 바이트는 비교 기준 원본 소스 읽기의 약15.9%다. 이것도 코드·Python·임시 배열·검증 파일의 모든 트래픽을 포함한 실제 지연 비율이 아니라 **명시한 원본 소스 예산에 대한 하한**이다. 읽기 단축만으로 콜드 실행 목표를 통과했다고 할 수 없다.

## 8. 405B 형태에서의 조건부 규모 계산

h16384, f53248, k1024, L126, V128256을 넣은 수식 계산이다. 해당 모델 실행이나 가중치 분포 측정이 아니다.

    P = L(2h²+2hk+3hf)+Vh
    남은 guarded MAC = 2Lhk+Vh

모든 잔차가 인증된다고 가정해도 guarded 단계에는 약1.568%의 projection이 남는다. 그 KV+head BF16 가중치가 약11.789GiB이므로 모두 GPU에 상주시키는 배치는8GiB를 넘는다. CPU/SSD로 나눠 둘 수 있지만 이동 비용을 증명해야 한다. 모든 배치의 불가능성 주장이 아니다.

전역 표의 크기는

    2 V (2Lk + V + h) = 103,294,304,256바이트 ≈96.200GiB.

KV표 약61.65GiB, logits표 약30.64GiB, 보존 임베딩 약3.91GiB다. 질의의 KV+logit 행은772,608바이트다. 외부 저장소에서 행만 가져오는 것은 가능해도 준비/저장 비용이 사라지지 않는다.

현재 생성 절차의 표 준비에는 `V(2Lhk+Vh)=811,758,482,620,416 MAC`이 필요하다. 토큰마다 해당 projection을 수행하는 명시적 루프의 계수 읽기만 약1.624PB다. 입력 배치로 더 잘 상각하는 생성기를 만들지 않았으며, 그렇게 하면 원본 연산 순서를 어떻게 보존하는지도 별도로 증명해야 한다. 표 초기화 검증 또한 현재 코드에서 전체 표를 읽는다.

현재 Python 생성기는 행렬과 표를 호스트 RAM에 통째로 만드는 곳이 있다. 96GiB 표의 스트리밍 생성/검증을 완성한 것이 아니다. 원본 체크포인트 보존, 추가 RAM/SSD/메타데이터, KV, allocator, 페이지·주소·복사·I/O가 추가다. 문맥131072에서 KV payload만63GiB이므로 범용 장문 실행도 별도 문제다.

따라서 이번 표가8GiB·TTFT·4BQ4 목표를 통과했다고 판정하지 않았다. **전역 인증 적용 범위와 콜드 비용 양쪽이 핵심 미해결 의무다.**

## 9. 의무와 다음 연구

| 의무 | 이번에 구성한 것 | 전체 목표 상태 |
|---|---|---|
| O1 | 원본 파일에서 정확한 L1 메타데이터, 전역 인증, 토큰 표 생성 | 일반 HF/모든 체크포인트 비용 OPEN |
| O2 | guarded·표 실행의 인과 KV·로그잇 전이 | no-RoPE 참조의 인증된 문맥에 한정 |
| O3 | endpoint 단조성, 분기 범위, 상태 귀납; C/Fraction 교차 검사 | library ABI 가정·실제 HF ABI OPEN |
| O4 | 준비·표·실제 source read/MAC·상태 dtype 구분 | 전체 RAM·I/O·정수 연산·지연 상한 OPEN |
| O5 | 목표 구조를 대입한 수식 비용 | GPU/405B/8GiB/4BQ4/TTFT NOT TESTED |
| O6 | 실행 소스·입력·KV·로그잇·해시·독립 수치 검사 | 전체 이론 formal proof 아님 |

보통 입력에서는 직접 참조조차 identity가 아니므로, 이번 경계를 정교하게 만드는 것만으로 임의 모델을 풀 수 없다. 큰 임베딩을 새로 만들거나 조밀 가중치에 유리한 구조를 심는 것을 모델 보존 목표로 바꾸지 않는다. 전역 identity 몫의 성공을 결정성만으로 일반 reachable-state 압축이 된다는 주장으로 바꾸지 않는다.

다음 핵심은 원본의 **비자명한 문맥 의존 전이**를 작은 준비 비용과 질의 비용으로 만드는 실제 관계다. 이 회차에서 그것까지 구성하지 못했다. 이 조건부 정리는 재사용 가능한 보조 결과로 남기되 핵심 엔진으로 승격하지 않는다.

## 10. 재현과 보존

`python run.py`, `python analyze.py`, `python -m unittest discover -s tests -v`, `python verify.py`로 실행한다. Python3.13, NumPy2.3.5, torch2.10.0+cpu, gcc를 사용했다. 초기 단위검사에서 클래스의 run 속성이 unittest 메서드를 가리는 이름 충돌이 있었고 수정했다. 초기 소스와 실제 실패 로그는 history에 보존한다. 입력·활성 표 검증과 메타데이터 일치·비유한 캐시 보호도 추가했다. 최종 수치 결과를 유리한 집단만 남기지 않았다.

19개 검사가 통과했고,455개 run 파일과2개 유도 파일이 새 디렉터리 재생성에서 일치했다. 전체 KV는 최종 파일에서 시간축 prefix로 복원할 수 있고, 매 시점 로그잇·토큰·RNG·접근 행렬 기록도 보존했다. 검증을 위한 해시 계산 비용을 실제 추론 성능 측정으로 보고하지 않았다.

공개 모델 로딩은 수행하지 못했다. 컨테이너에는 transformers가 없고 HF 요청은 DNS 실패, 별도 다운로드는 URL 조회 검사에서 실패했다. 인프라 실패를 이 알고리즘의 과학적 기각으로 세지 않았다. 실제 공개 모델·RoPE·CUDA·목표 자원/지연·Actions·전체 저장소 검사는 실행하지 않았다.

원격 커밋/브랜치/PR은 별도 실제 receipt가 있어야 확정한다. 이번 보고서의 조건부 성과와 원격 인계는 다른 축이다. 원격에는 소스 캡슐·사전등록·증명·검증 요약이 보존되며, 전체 원시 입력·KV·표와 초기 개발 로그는 사용자 ZIP에 있다. 원격 소스에서 과학 결과를 재생성해 최초 manifest와 대조할 수 있다. 모든 바이너리 로그가 Git에 내장됐다는 뜻은 아니다.
