## 2. Principle I — query-side complete sparse image frame

### 2.1 Reversed premise and finite compiler

Instead of compiling a checkpoint-dependent runtime program, make the current
right factor itself produce the addresses.

For an arbitrary binary `m x n` matrix, partition the input coordinates into
finite blocks `B`. For every nonzero local pattern `p` compile the exact image:

```text
Y[B,p] = W_B p  in F2^m.
```

The representation is the finite collection of packed `Y[B,p]`. Query runtime
parses the current vector block-by-block. The local query bits are the table
address; zero blocks do not read an image. The decoder is:

```text
Wv = XOR_B Y[B, v_B].
```

No checkpoint-dependent instruction stream is fetched. The naive constructor is
finite with upper bound:

```text
sum_B (2^|B|-1) * m * |B|  binary operations.
```

Persistent transformed payload is:

```text
m * sum_B (2^|B|-1) bits.
```

The implementation exhaustively matches direct GF(2) MatVec on the registered
small control family.

## 3. Principle II — exact weight-value inverted native executor

### 3.1 Finite compiler and exactness

For every input column `j`, group rows by the exact finite leaf descriptor used
by the declared reference multiplication. Store the descriptor plus its row
membership list. At runtime compute one exact product per distinct descriptor:

```text
p = NativeLeaf(weight_descriptor, x[j])
```

and feed that identical leaf word to every member row. Columns are still visited
in reference order and every row performs the same ordered additions as the
direct implementation. Therefore, for the declared deterministic finite-word
leaf/add ABI, every row receives identical leaf bits in identical reduction
slots and the result is exact.

The finite implementation was checked against direct ordered MatVec. This is a
real exact executor for its declared ABI, not a floating-point reassociation.

### 3.3 Stronger state-dependent coalescing adversary

The final source strengthens P2 beyond static weight classes. Runtime is allowed
to group rows by the dynamic transition key:

```text
(current accumulator word, current weight word).
```

Rows sharing that pair have the same deterministic next accumulator word, so the
coalescing algorithm is exact.

Now use the explicit family:

```text
first column weights:   1,2,...,m
later column weights:   all 1
query values:           all 1
zero accumulator:       0
```

For `m=n=16,384`, every running integer stays below `2^24`, so these integer
multiplications/additions are exactly representable in IEEE FP32. After the
first column the row accumulators are all distinct; adding the common `1`
preserves distinctness. Hence every column has `m` distinct
`(accumulator,weight)` transitions and the coalescer performs:

```text
state/weight pair updates     268,435,456
baseline scalar leaf updates  268,435,456
update fraction               1.0
```

This rejects static value-class and this stronger identical-state-transition
sharing as universal >=90% arithmetic-removal cores. It does **not** reject all
possible state machines or all nonlinear aggregation.

## 4. Principle III — encoded-state safe gauge

### 4.1 Exact safe arm

Carry each wire in compiler-chosen encoded coordinates. The universally safe
native arm is a coordinate permutation `P`:

```text
z = P h
W' = P_out W P_in^-1
```

Elementwise operations remain elementwise up to the same permutation, residual
adds are aligned, and cache/state layouts carry the inverse map. Induction over
the graph therefore preserves exact native state and RNG. But row/column
permutations preserve the number of nonzero coefficients, so a worst-case dense
matrix remains dense.

### 4.2 Arbitrary nonlinear meet-preserving bijections collapse to permutations

The binary necessary-condition algebra uses coordinatewise AND as the
Hadamard/gating primitive. Let a bijection

```text
T : {0,1}^n -> {0,1}^n
```

satisfy:

```text
T(x AND y) = T(x) AND T(y)
```

for all `x,y`. Then `T` is a coordinate permutation.

Proof:

1. AND is the meet operation of the Boolean lattice.
2. `x <= y` iff `x AND y = x`; meet preservation plus bijectivity makes `T` an
   order automorphism.
3. Order automorphisms preserve the minimal nonzero elements (atoms).
4. The Boolean-lattice atoms are exactly the coordinate basis vectors.
5. Therefore `T` permutes those atoms.
6. Every Boolean vector is determined by the set of atoms below it, so the whole
   map is exactly the induced coordinate permutation.

Exhaustive finite controls over **all bijections** through `n=3` agree:

```text
n=1: 2 bijections,      1 meet preserving, 0 non-coordinate
n=2: 24 bijections,     2 meet preserving, 0 non-coordinate
n=3: 40,320 bijections, 6 meet preserving, 0 non-coordinate
```

### 4.3 Independent linear input/output gauges do not escape

The final strengthening allows three different invertible linear maps at a
product node:

```text
C(x AND y) = A(x) AND B(y).
```

Write `a_i=A e_i`, `b_j=B e_j`. For `i != j`, cross terms require
`supp(a_i) cap supp(b_j)=empty`. If coordinate `k` lies in `supp(a_i)`,
invertibility of `B` requires row `k` to occur in some `b_j`; cross-disjointness
forces `j=i`, so `supp(a_i) subseteq supp(b_i)`. Symmetry gives equality.
The `n` nonempty equal support sets are pairwise disjoint inside `n` output
coordinates, hence every set is a singleton and together they form a coordinate
permutation. `C e_i=a_i AND b_i` is the same singleton. Thus:

```text
A = B = C = one aligned coordinate permutation.
```

Exhaustive linear controls give:

```text
n=1: 1 triple checked,   1 isotopy
n=2: 216 triples checked, 2 isotopies
non-aligned/non-permutation survivors: 0
```

Therefore a gauge cannot secretly make an arbitrary dense operator sparse while
keeping the same cheap coordinatewise product, even with independent linear
input/output gauges.

Claim boundary: this does **not** reject encoded-state methods that explicitly
construct and pay a transformed nonlinear operator. It rejects the safe-gauge
route in which the nonlinear primitive remains coordinatewise/free.
