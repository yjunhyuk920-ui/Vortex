# 공동 정보에서 소비자별 최소 선형 정보로: 유한 생성, 원본 범위 미연결

2026-09-08. 부모 PR146/66c01825635a357f86f9dfa5369088d7a239c92d.
이전 중단된 작업의 원시 자료를 실제 PC에서 재조회한 뒤 이어간 기록이다.
전체 목표와 O1-O6 양화는 MISSION/CTC 그대로다. `THEORY_STATUS=NOT_ESTABLISHED`,
`HARDWARE_STATUS=NOT_TESTED`, `CORE_ADMISSION=false`. 전체 O1-O6 새 CLOSED는 0이다.

## 1. 이번에 실제로 추가한 생성 절차

이전 Source는 질의마다 위치 ID를 읽어 모든 공동 패턴의 빈도표를 만든다.
이번에는 사용자가 실제로 필요한 함수 집합 F를 생성기의 입력으로 넣고,
그 함수들에만 충분한 비트 평면을 직접 생성한다. 원본 정보 일부를 버리고
일반 모델과 같다고 주장하는 방식이 아니다. 정확성의 범위는 고정된 F에
대한 선택 위치 XOR 질의이며, 새 함수 또는 다음 상태가 요구되면 다시 검증해야 한다.

서로 다른 관측 패턴 집합을 P, 그 첫 패턴을 p0라고 하자.
각 f의 중심화된 행을 V[f,p]=f(p) XOR f(p0)로 만든다. F2 Gaussian elimination으로
실제 기저 함수 b1,...,br와 계수 d_fj를 생성하고, 모든 p에서 관계를 다시 검사한다.

    f(p) = c_f XOR XOR_j d_fj b_j(p),   c_f=f(p0).
    Y_f(q) = c_f parity(q) XOR XOR_j d_fj parity(q AND plane_j).

plane_j의 i번째 비트는 b_j(p_i)다. 표준 Boolean 선형대수와 정적 부분평가를
이용한 구체적인 구성이지, 새 수학 분야나 목표 엔진을 발견했다는 주장은 아니다.
기존 코드의 히스토그램 생성은 질의 단계에서 없어진다. 대신 원본 전체에서
평면을 만드는 준비 비용을 지불하고, 질의 때 실제 평면 단어들을 읽는다.
실행 객체는 원본 값 배열/패턴 사전/함수 AST를 받지 않고 파일만 읽는다.
원본 체크포인트는 별도로 그대로 보존하며 그 저장비를 제외하지 않는다.

## 2. 정확성, 종료 및 최소성의 정확한 범위

위 식은 위치마다 성립하는 식을 선택된 위치에서 XOR해 증명한다. 원본 계수와
질의의 우연에 기대지 않으며, 지원하는 모든 마스크에서 정확하다. 생성기는
관측 패턴 정렬, 함수 평가, 유한 소거, 검증, 평면 포장 순서로 종료한다.
질의는 r 평면과 F 계수 마스크를 읽는 유한 루프다. 실패하면 원본 재실행하는
구조도 아니며, 선언한 도메인에서 항상 반환한다. 도메인 밖은 ValueError다.

현재 형식에서 r은 최소다. 다른 s개 평면과 상수항의 선형 XOR 읽기가 모든
한 위치 마스크에서 같은 F를 반환한다면, 중심화 함수행렬 V가 폭 s를 통해
인수분해되므로 rank(V)<=s다. 생성기는 r=rank(V)를 사용한다.
이는 이 선형 평면/XOR 읽기 형식의 최소성이지 모든 비선형 자료구조/회로/
적응형 읽기의 하한이 아니다. r이 크다고 모든 알고리즘의 비용이 크다고 하지 않는다.

identity bit 함수들이 F에 포함되고 P에 0과 k개의 단위벡터가 있으면 V에는
k차 단위 부분행렬이 있으므로 r>=k다. 다음에 필요한 정보를 보존하면
유리한 작은 r 가정이 깨질 수 있다는 형식별 증거이며, 실제 모델의 KV가
반드시 이런 함수를 노출한다고 주장하지 않는다.

## 3. 사전에 고정한 추가 실행의 결과

기존 24개 자료의 모든 마스크와 추가 12개 자료를 합쳐 6,336질의/292,288출력비트가
직접 ANF 계산과 일치했다. 이 수는 신경망/토큰 실행 수가 아니다. 예전 자료의
재검사는 새 과학 데이터처럼 세지 않는다. 독립 파서/스칼라 논리 참조와
단위 검사는 별도의 검증 기록으로 남긴다. CPU/GPU 속도 측정은 하지 않았다.

N=1024,k=32 두 고정 씨드에서 하나의 비선형 함수만 요구하면 r=1이다.
원본 packed 4096B 대비 파일186B, 실제 평면읽기128B, 입력마스크/계수/출력까지
지정해 센 필드 참조387B다. 함수 하나를 정적으로 미리 계산하는 부분평가다.
이것을 405B의 원본 출력/다음 상태에 필요한 전 정보를 생성한 것으로 부르지 않는다.

같은 원본에 원래 32비트의 질의도 추가하면 r=33, 파일4478B, 평면읽기4224B,
지정 필드참조8807B가 됐다. 작은 소비자 집합을 위한 정확한 생성은 구현했지만,
필수 소비자가 늘어나는 상황에서도 저렴하게 유지되는 구성은 만들지 못했다.
비트 평면을 실제 64비트 청크로 읽지만 이는 Python 코드이며 GPU 명령으로
실행된 것이 아니다. 큰 정수 shift/AND와 임시 객체 비용도 여전히 지불한다.

## 4. 전 비용: 포함한 절차와 미확립인 상수

N=원본 위치 수, k=원본 비트폭, R=관측패턴 수<=N, F=함수 수,
L=총 ANF 단항식 수, r=중심화 rank, nb=ceil(N/8), rb=ceil(r/8).

    파일 바이트 D=56+F*(1+rb)+r*nb.
    named query bytes = r*nb + F*rb + F + (r+1)*nb + F.

56B는 헤더24와 SHA256다이제스트32. 코드/원본/증서/로드된 객체를 포함한 전체
메모리가 D라는 뜻이 아니다. 로더는 전체 파일 해시/계수/평면 padding을 검사한다.
해시는 무결성 점검이지 원본 함수와의 등가 증명이 아니다.

생성은 원본 Nk비트 읽기, 정렬/사전화, (R+1)L개의 k비트 단항식 검사,
최대 F*r개의 길이 R/r 비트열 소거, 동등한 규모의 증서 검사,
N*r회의 평면 비트 생성, 파일 포장과 해싱을 수행한다.
본 Python의 긴 shift/sum도 무료가 아니다. 보수적인 비트 작업 상한에는
O(N^2*k + (R+1)*L*k + F*R^2 + F*r*(R+F) + N*r*(N+R*k+log R)+D*8)를 쓸 수 있다.
정렬/해시 테이블은 선형/로그 최적이라고 가정하지 않고 충돌 비교까지
O(N^2*k)에 포함한다. 입력 인덱스 연산의 logN 인자와 함수 AST를 포함한
고정 폭 RAM 구현의 더 정밀한 상한은 별도이다. 이것은 초 단위의 실제
VORTEX 충분 상한이 아니다. 임의 크기 Python 객체 allocator 상수도 미확립이다.

질의는 mask의 nb바이트화/검사, parity, r*ceil(nb/8)회의 최대64비트
AND/popcount, r비트 결과 조립, F회의 r비트 마스크 AND/parity, 출력쓰기를 한다.
보수적인 bitwork는 O(N+r*N+r^2+F*r+F), 임시 payload는
O(N+r+F)비트 외에 Python 객체/슬라이스/주소/code/cache 비용이다.
생성 peak payload에는 원본/정렬본 O(Nk), 사전 O(Rk), 행 O(FR),
계수 O(Fr), 평면 O(rN), 원본 보존 및 출력파일 복사가 모두 들어간다.

초기화+H회 비용은 T_construct+T_validate+T_store+T_load+
sum_{t=1}^H(T_mask+T_planes+T_decode+T_output+T_alloc+T_service)다.
원본 한 번 읽기만으로 원본을8회읽는 비교의12.5%이므로, 질의 일부 필드가
10%아래라는 사실로 짧은 세션 전체10배를 말할 수 없다. 겹침스케줄/서비스보장,
baseline 하한 또는 coupled ratio, workload분포는 없으므로 O4/O5는 OPEN이다.

## 5. native 순서와 원본 다음 상태까지의 실제 빈칸

기존 `[2^24,1,-2^24,1]`과 `[2^24,-2^24,1,1]`은 같은 공동 개수/정확합을
가지지만 FP32 균형 합은1과2다. 이번 평면은 위치를 보존하지만 parity 읽기는
일반적인 ordered reduction을 수행하지 않는다. 원래 순서대로 평면/ID를
복원하는 기존 후속 실행은 정확하지만 모든 위치를 읽는다. 입력마다 달라지는
FP32 product들을 생산하는 비용을 없애지도 못했다.

전체 원본 전이의 실제 대체 연산이 모든 live output비트를 같게 만들고, RNG
호출 횟수/순서와 외부상태 쓰기를 유지한다면 귀납으로 미래 동작이 같다.
그러나 여기서 fixed F가 모든 native/RNG/KV 소비자를 포괄한다는 증명/생성기는
없다. 현재 결과가 같은 두 원본이 나중 bit0 질의에서 갈리는 단위 반례도 보존한다.
random.Random은 실험 자료 생성용이며 원본 모델 RNG 검증이 아니다.

다른 두 원리 B/C는 기존 반론을 뒤집을 새 separator/비열거 native conjugacy를
구성하지 못했다. 조건부 세 원리를 비교한 것이지 세개의 통과한 발명이 아니다.
실행하지 않은 B/C는 NOT TESTED다. 실패한 A를 사전크기/씨드 증가로 다시
주요 후보로 채택하지 않는다. 이번 종료는 증거를 인계하는 세션 경계이며
이론 완료가 아니다.

## 6. 다음 핵심 작업

`native_current_input -> all_required_joint_effects -> exact_successor`를 위한
유한 생성 절차가 여전히 필요하다. 소비자 특수화 후에도 남는 live 함수들의
생성비가 기준선보다 작아지는 새로운 이유를 증명해야 한다. native 제품들을
먼저 모두 구하거나, 작은 rank/작은separator/작은상태를 가정하면 통과가 아니다.
새 B/C 후보는 실제 구성 규칙과 충분 비용 상한부터 제시하고, 이를 얻기 전
큰 truth table/SMT timeout/더 많은 합성 자료로 확장하지 않는다.

공개 checkpoint, HF forward, CUDA, 원본 전체 RNG/KV, 405B, GPU peak8GiB,
native4BQ4 p50/p95, TTFT, 전체 저장소 suite: NOT TESTED.
이전 실패 근거와 초기 해시는 수정하지 않는다. 원격 커밋은 재현/인계이며
O1-O6 달성의 증거를 대신하지 않는다.
