# 전수 응답표 없는 원본 수치 프로그램 생성: 제한형 구성과 비용 판정

`de11732ec478773164aeb2cf7de02efd0483c9e9`.

## 1. 판정과 고정 목표

**이번 결과는 작은 수치 프로그램을 원본 식에서 직접 생성·검증하는 보조 구성이다. 405B용 핵심 실행기가 아니다.**

임의의 공개 미수정 HF dense405B, 실행기만 교체, batch1, 단일 GPU 전체 peak<=8GiB,
원본 출력/RNG/필요한 다음 상태, 같은 머신 native4B Q4 대비 p50<=1.2x,p95<=1.5x와
기존 TTFT라는 목표는 그대로다. 준비/저장/RAM/SSD/이동/계산/상태/검증 비용을 모두 포함한다.

`THEORY_STATUS=NOT_ESTABLISHED`, `HARDWARE_STATUS=NOT_TESTED`, `CORE_ADMISSION=false`,
`FULL_MISSION_O1_O6=OPEN`, `THREE_QUALIFYING_NEW_PRINCIPLES=false`.

직전 결과의 Q^n 응답 열거를 없애는 실제 생성 절차는 만들었다. 그러나 이것은 기존
CEGIS/SMT/컴파일러 연구의 제한형 적용이다. 세 개의 새로운 >=10배 원리를 발명했다고
주장하지 않는다. 기존 F-040이 금지한 'SAT를 쓰면 임의 모델이 작은 hot core가 된다'는
가정을 다시 채택하지 않는다. 준비비용을 입증한 범용 작은 프로그램 합성도 아니다.

## 2. 세 경로 비교와 가장 싼 검사

| 경로 | 전환한 계산 순서 | 비용과 결정적 빈칸 | 이번 작업 |
|---|---|---|---|
| A. 원본 식 -> 짧은 후보 -> 전 입력 반례 검사 | 모든 입력의 답 대신 원본 연산식을 사용 | 작은 후보의 존재, 검증 서비스 시간, 가중치 읽기 절감이 보장되지 않음 | 유한 후보 문법과 상수 기반 합성 규칙만 구현 |
| B. 일부 관측 응답 + 예외 목록 | 전체 표 대신 발견한 예외만 저장 | 관측하지 않은 입력의 누락을 보장하려면 별도 전 입력 증명이 필요 | 응답표/표본 확대 안 함 |
| C. 현재 입력의 출력 비트가 강제될 때까지 원본 제약 풀이 | 실행 대신 질의별 논리 문제 풀이 | 원본 제약 생성/읽기와 풀이 비용이 무료가 아님 | 대형 백엔드 안 만듦 |

어느 경로에도 전체 목표의 >=10배 상한이 없으므로 핵심 승인하지 않았다. A의 미정의
생성기를 유한 프로그램으로 만드는 범위의 보조 검증만 수행했다. 거부 사례나 작은
정리의 개수를 목표 달성 가능성이 높아졌다는 증거로 쓰지 않는다.

## 3. 선언한 수치 계약

입력은 16비트 BF16의 유한한 65,280개 표현 전체다. 부호 있는 0과 비정규수도 포함한다.
실행 시 작은 입력 알파벳으로 양자화하지 않는다. 입력 NaN/무한대는 이 보조 계약 밖이다.
FP32 곱/덧셈은 각각 round-to-nearest ties-to-even, BF16 저장도 같은 반올림이다.
FTZ/DAZ는 허용하지 않고 C 실행기는 이를 검사한다. FMA는 명시한 경우에만 사용한다.
출력 NaN은 이 참조 계약에서 0x7fc0(BF16), 0x7fc00000(FP32)로 정규화한다.
NaN payload/예외 플래그를 원본 GPU와 일치시켰다는 주장은 없다.

Z3의 IEEE 부동소수점 이론으로 AST를 번역했다. 현재 출력뿐 아니라 선언한 모든 상태
루트에 대해 다음 불일치가 존재하는지 묻는다.

    exists x in finite_BF16^n:
      bits(P(x), successor_P(x)) != bits(C(x), successor_C(x))

SAT이면 반례를 C 실행으로 확인하고 후속 후보를 제거한다. UNSAT일 때만 그 후보를
동등하다고 채택한다. UNKNOWN/시간·자원 제한은 통과가 아니다. 생성 시 원본을 유지하는
것은 안전한 비최적화이지, 성공한 가속 또는 질의 시의 근사 실패 fallback이 아니다.

SMT-LIB 식, 버전, 상태, 반례와 선택 프로그램을 저장한다. Z3 결과의 재실행은 같은
솔버를 신뢰하는 검사이며, 독립 증명 검사기로 UNSAT 증명 로그를 확인한 것은 아니다.
C 및 Fraction 대조는 표본 수치 확인이지 모든 SMT 정리의 독립 증명은 아니다.

## 4. 실제 생성기와 첫 단계

입력 AST의 상수, 그 합, 0/입력 반환, FMA 등 사전에 고정한 유한 문법으로 후보를 만든다.
후보 수는 사례당 최대16, SMT 호출당 timeout8초/rlimit2,000,000/seed7이다. 모든 입력을
실행해 응답행렬을 만들지 않는다. 문법 밖의 작은 프로그램을 찾는다는 보장은 없다.

7개 사례 중 solver가 채택한 축약은 두 개다.

- FP32 중간값의 `(3/8)x+(1/8)x` -> `(1/2)x`: UNSAT, 선언 영역에서 동등.
- 출력 `x-x`를 +0으로 교체하되 다음 상태 `x`는 보존: UNSAT.

중간 곱을 각각 BF16에 저장하는 식과 두 입력 FMA 후보는 UNKNOWN이었다. 원본을
유지했으며 예산을 늘려 통과시키지 않았다. 부호 있는0, overflow로 생기는 NaN,
다음 상태 삭제는 SAT 반례로 거부했다. 전체7개 선택 프로그램의 C 재생 28,678회에서
BF16 불일치0이다. 이 중 원본 유지도 포함하므로 28,678회 가속 성공이 아니다.

## 5. 다음 구성: 풀이 시간 대신 연산별 증명 조건 사용

첫 단계 결과를 보존하고 FOLLOWON.md를 고정한 다음, 단항 곱의 정확성에서 합성법을
유도했다. 원본 BF16 계수 c를 기약형 c=sign*s*2^k(s는 양의 홀수)로 놓자.
다음은 보수적인 충분조건이다.

    |c| <= 1, k >= -16, bit_length(255*s) <= 24.

c=0은 부호를 유지해 별도 처리한다. c가 실제 BF16 값인지도 검사한다.

**증명.** 유한 BF16 x의 유효 이진 자릿수는 최대8개이고 최소 공통 단위는2^-133이다.
계수와 곱한 유효 자릿수는24개 이내이며 곱의 공통 단위가2^-149보다 작지 않다.
|c|<=1이므로 크기는 최대 유한 BF16을 넘지 않아 FP32에서 overflow하지 않는다.
정규수 또는 FP32 비정규수로 정확하게 표현된다. ±0 곱의 부호도 두 실행에서 같다.
따라서 FP32 곱 반올림이 실제 값을 바꾸지 않는다.

이 조건에서 누적값 a에 대해

    RN32(a + RN32(c*x)) = FMA32(c,x,a)

가 성립한다. 곱이 정확하므로 두 식의 유일한 실질적 반올림은 같은 덧셈이다. 무한
누적값/NaN은 선언한 canonical output 규칙 아래 처리한다. FP 예외 플래그는 계약 밖이다.

같은 입력 x를 두 번 쓰고 계수 a,b가 같은 0 아닌 부호이며, a,b,a+b가 각각 위 조건을
통과하고 a+b 자체가 정확한 BF16 값이면

    RN32(RN32(a*x)+RN32(b*x)) = RN32((a+b)*x)

로 합친다. 이 규칙은 원본 입력 leaf에만 적용한다. 이미 FP32 덧셈을 수행한 중간값은
BF16 입력과 같다고 취급하지 않는다. 중간 BF16 store를 가로질러 적용하지도 않는다.
생성기는 상수 비트와 노드 종류를 검사해 조건이 맞는 경우에만 변환한다.

안전성 발견·수정: 개발 중 동일 operand 조건이 임의 FP32 중간식에도 적용될 수 있어
입력 leaf 조건을 추가했다. 이 경우를 거부하는 단위 검사를 보존했다. 최초 source와
pilot 결과는 history/stage1에 별도로 유지했으며, 최종 결과는 수정본에서 재생성했다.

## 6. 아주 작은 값에서 생기는 실제 반례

u=2^-133, x=3u(BF16 비트0x0003)일 때:

    RN_BF16(3*x/8)=u
    RN_BF16(x/8)=0
    RN_BF16(u+0)=u                 -> 0x0001
    RN_BF16(x/2)=RN_BF16(1.5u)=2u -> 0x0002

동일한 대수식도 중간 저장 위치가 다르면 달라진다. 이 반례는 C와 독립 Fraction
반올림으로 확인했다. 첫 단계 UNKNOWN을 나중에 UNSAT로 바꿔 적지 않았다.
별도 구성한 반례로 이 직접 축약을 명확히 거부한 것이다.

상태 반례에서는 현재 출력 x-x가0이어도 다음 상태 x를 삭제하면 다른 프로그램이다.
이번 검사는 단순한 상태 루트만 다루며 Transformer KV/RNG 전이를 증명한 것은 아니다.

## 7. 행렬 생성·직렬화·실행 결과

실제 BF16 계수 행렬을 읽어 순차 FP32 projection AST와 변환 AST를 생성한다.
선택 AST를 JSON 파일로 저장한 뒤 다시 읽어 C 실행기에 전달했다. 해석기는 입력/출력
각128, 노드8192의 제한이 있다. 큰 HF 모델용 스트리밍 로더나 GPU 실행기는 아니다.

등록한4개 합성 행렬,448개 벡터 질의에서 FP32 좌표1,664개와 BF16 좌표1,664개가
원본C/변환C/원본Fraction/변환Fraction 사이에 모두 일치했다. 일반 BF16 계수의 극단값은
안전조건을 통과하지 않으면 원본 곱을 유지했다. 공개 체크포인트를 사용하지 않았다.

| 행렬 | 원본 표현 연산 | 변환 표현 연산 | 원본/변환 상수 바이트 | 원본/변환 명령 바이트 |
|---|---:|---:|---:|---:|
| 4x8 |60|32|124 / 124|1584 / 1136|
| 4x16 |124|64|244 / 244|3216 / 2256|
| 4x32 |252|128|492 / 492|6512 / 4528|
| 2x4 극단 계수 포함 |11|7|24 / 24|336 / 272|

**FMA 하나를 표현 연산1개로 센 표다. FMA 안의 곱셈과 덧셈이 사라진 것은 아니다.**
4x32는 원래128곱+124합이고, 변환 후4곱+124FMA이므로 산술작업은 그대로다.
원본 BF16 행렬은256바이트인 반면 선택 명령만4528바이트이고 root16바이트 등도 더해진다.
이 값은 정의한 C bytecode 계측이며 JSON 파일 크기/실제 메모리 트래픽/지연과 다르다.

## 8. 전 비용 및 확대 관문

Q^n 원본 응답 생성은 없지만 원본 계수 전체를 읽고 식을 만들어야 한다. A단계 솔버
비용도 준비비용이며, timeout 상한은 성공한 증명의 서비스 상한이 아니다. bounded
문법에 속하는 후보를 시험하는 것만 유한 종료가 보장되고 유용한 후보의 발견은 보장하지
않는다. 일반 합성 문제의 빠른 시간 상한을 얻지 않았다.

B단계 규칙의 방문수는 노드에 비례하지만 실제 Python tuple hashing/비교는 부분식을
재귀적으로 방문하므로 현 구현을 무조건 선형시간이라고 부르지 않는다. 펼쳐진 식
크기 V 기준으로 보수적인 이차 작업을 허용한다. AST/코드/계수/증거/작업공간을 별도로
저장한다. 질의 wrapper는 tuple을 다시 순회해 C명령 배열로 바꾸는 일도 한다.

일반 조밀 행렬의 계수 정보는 남고 매 질의의 계산도 남는다. 개선 없는 원본 유지는
10배 가속 성공이 아니다. FMA는 기존 하드웨어 연산이며 새 기술이라고 주장하지 않는다.
405B 스케일의 총 VRAM/초기화/TTFT/4BQ4대비지연 상한은 없고, 실제 측정도 하지 않았다.

## 9. 증명 의무와 원장 추가분

| 의무 | 이번 보조 결과 | 전체 목표 상태 |
|---|---|---|
| O1 자동 생성 | 작은 AST/행렬에서 유한 생성기; 전수 응답표 없음 | OPEN: 임의 HF/목표비용 |
| O2 인과 실행 | 현재 입력과 생성코드 C실행 | OPEN: 전체 prefill/decode/KV |
| O3 원본 동작 | 선언 FP32/BF16 규칙, ±0/비정규수/상태루트 검사 | OPEN: 실제 ABI/전체 RNG·상태 |
| O4 전체 비용 | 명령/상수/탐색/래퍼 비용 구분 | OPEN: 목표 전체 상한 |
| O5 목표 규모 | 가중치읽기 및 산술 제거 없음, 핵심 미채택 | OPEN: 8GiB/지연/TTFT |
| O6 독립 증거 | 소스/SMT/C/Fraction/재생성; 솔버 신뢰 명시 | OPEN: 전체 정리 증서 |

결정: 제한형 source constructor와 안전 수치 규칙으로만 보존한다. 일반 소스 생성기가
존재한다는 말에서 곧바로 작고 빠른 소스가 생성된다는 결론으로 넘어가지 않는다.
실패 범위: 이 유한 문법과 두 국소 규칙은 일반 가중치의 대부분 읽기·연산을 제거하지
못했다. 모든 프로그램 합성의 불가능성이나 rank 기반 읽기 하한은 주장하지 않는다.
가정: 정확한 입력형, RNE, 비정규수보존, canonicalNaN, 정해진 상태root, bounded인터프리터.
설계: 원본AST -> 유한후보/guard -> 검증 또는 원본유지 -> JSON -> C명령 -> 출력.
다음: solver예산/문법을 늘리는 것이 아니라, 실제 가중치 정보 대부분을 질의경로 밖에
남겨도 되는 비국소 계산관계와 그 관계의 저렴한 생성·상태 갱신 방법이 먼저 필요하다.

## 10. 재현과 출처

`README.md` 명령으로 C를 빌드하고 `run.py`, `followon.py`, 단위검사, 저장된
EXPECTED_MANIFEST.json과의 비교를 수행한다. 22개 검사,56개 과학파일의 재생성 일치.
독립 FP32 좌표검사는 같은 고정 입력에 나중에 더한 강화 검사이며 씨드·비용 기준을
관측 후 조정하지 않았다. 실행환경/로그/최초결과/반례도 사용자ZIP에 보존한다.

Z3 Python package 설치는 DNS오류로 실패했고, 이미 설치된 libz3.so.4(4.13.3.0)의
