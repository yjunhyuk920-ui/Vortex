# native full-rank 변환 검토

행렬이 수학적으로 full-rank라고 해서 반올림을 포함한 실제 연산이 입력을
구별하는 것은 아니다. 대각 2, 나머지 1인 dense 행렬과 명시한 BF16 입력
구간에서는 서로 다른 `256^(n-1)`개 입력이 같은 FP32 출력으로 합쳐진다.
원래 곱셈과 각 덧셈의 반올림을 따라가며 이를 증명했다.

입력과 출력을 일대일로 다시 표시해도 합쳐진 입력 수는 바뀌지 않는다.
따라서 이 연산을 가역 인코딩만으로 정보를 모두 보존하는 좌표 복사로
바꿀 수 없다. 16,384 폭에서는 같은 출력에 대응하는 입력이 적어도
`2^131064`개다. 추가로 입력을 복원해야 하는 방식이라면 이를 구별하는
상태가 필요하지만, 이는 일반 native 실행이나 KV에 필요한 메모리 하한이
아니다. 다른 입력을 유지하는 전역 실행, 비가역 상태 표현, 다른 decoder는
여전히 별도 연구 대상이다.

3차원 입력 65,536개를 실제 열거해 출력 단어 196,608개를 확인했고 불일치는
없었다. 16,384 폭 검사는 양의 0만 있는 부분을 생략해도 원래 트리와 같다는
증명을 이용한 제한된 입력 검사다. 전체 dense 연산이나 405B GPU 실측을
한 것으로 기록하지 않는다. 실제 HF에서 해당 hidden-state 입력들이
도달 가능한지 보여 주는 trace도 이번 범위에 없다.

주소 라우터, Patricia 구조, literal rank-normal 변환의 기존 실패 근거는
유지한다. 이번 결과는 마지막 방식의 native 정확성 조건 하나를 분명히 한
것이며, 새 실행 원리 3개나 목표를 만족하는 범용 실행기를 얻은 결과가 아니다.
다음에는 native 비가역 연산과 다음 상태를 실제로 만드는 유한 프로그램을
제시하고, 인코더나 decoder 안에서 원래 dense 연산을 다시 수행하지 않아야
한다.

O1~O5 OPEN, O6 PARTIAL. THEORY_STATUS=NOT_ESTABLISHED,
HARDWARE_STATUS=NOT_TESTED, CORE_ADMISSION=false.
원본 출력·RNG·다음 상태·KV, 전체 비용, 단일 GPU 8GiB 및 native4BQ4 대비
지연 기준은 바뀌지 않았다. 405B 하드웨어는 현재 없으며 지속 목표는 미달성이다.

[results/summary.json](results/summary.json)을 참조한다.
