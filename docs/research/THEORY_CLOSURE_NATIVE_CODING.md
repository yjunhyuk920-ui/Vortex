# VORTEX — 원본 연산 코드의 이론 완성 시도와 남은 증명 의무

2026-09-05. 원격 기준 `ab08dbb0f6665e6207c4a1d14a0d0677146f4542` (PR #124).
사용자의 요청은 새 보조 실험이 아니라 **고정 목표를 충족하는 이론의 완성**이다.
이번에도 그 이론을 완성하지 못했다. 아래의 증명은 특정 추론의 적용 범위를 정하는
보조 결과이며, 값싼 정보 생성기나 VORTEX 전체의 불가능성 증명이 아니다.

```text
THEORY_STATUS=NOT_ESTABLISHED
HARDWARE_STATUS=NOT_TESTED
CORE_ADMISSION=false
FULL_MISSION_O1_O6=OPEN
```

## 1. 완성해야 하는 명제

원본 수치 ABI를 A, 체크포인트를 W, 합법적 입력/문맥을 x, 원본 상태를 s,
RNG 상태를 r이라고 하자. 원본 한 단계는

    F_A,W(s,x,r) = (관측 가능한 출력, s_next, r_next)

이다. 목표는 유한한 자동 구성기 E와 인과적 실행기 G, 상태 대응 관계 R을
**실제로 구성**하여 초기 대응과 모든 합법적 후속 실행에서의 대응을 증명하는 것이다.
외부 logits를 제공하는 원본 인터페이스라면 logits도 관측에 포함한다. 압축 상태에는
정확한 continuation 관계가 필요하며, 참조 실행을 다시 호출하는 비용을 숨기지 않는다.

또한 전체 GPU 할당이 8 GiB 이하이고 동일 머신 native 4B Q4 대비 warm time/token
p50 <=1.2배, p95 <=1.5배이며 기존 TTFT 요구를 만족하는 충분한 시간 상한이 필요하다.
재학습·가중치 변경·대상 축소·숨은 외부 계산·무료 전처리·복구는 허용하지 않는다.
ABI, 문맥 범위, baseline, 지연 모집단의 미고정 항목은 승격 전에 고정해야 한다.
그러나 이번 미완성은 그 평가 항목만의 문제가 아니다. **핵심 알고리즘도 없다.**

상태별 상한에는 입력 처리, 코드/주소 생성, 저장·전송, 수치 연산, 출력과 KV/RNG,
검증·복구·동기화가 전부 들어가야 한다. 초기 구성과 짧은 세션 비용은 따로 지불한다.
지속 처리량의 보장 없이 최대 대역폭으로 나눈 값을 시간 상한으로 사용하지 않는다.

## 2. 세 경로를 다시 비교한 결과

새로운 이름 세 개를 발명했다고 주장하지 않는다. 이전의 세 정보 생성 방향을 최신
자료와 실제 수치 의미론으로 다시 검토했다. 어느 경로도 핵심 채택 조건을 충족하지 않았다.

| 경로 | 구체적인 계산 절차와 10배 경로 | 해결되지 않은 부분 |
|---|---|---|
| 큰 오류를 허용하는 코드/자기정정 | 변환된 질의를 계산하고 코드에서 답을 복원. k회 약한 계산 + 변환 + 복원이 원본의 1/10 이하여야 함 | 빠른 약한 계산기의 자동 구성과 정확도 보장 자체가 필요하다. 유한체/정수 정리는 native 반올림 함수의 선형성을 주지 않는다. 확률적 성공도 결정적 exact 계약으로 승격할 수 없다. |
| 구조적 delta-tree 계산 | 열의 threshold 표현과 차이 트리를 전처리하고, 질의 때 anchor와 edge 차이를 전파. 전처리·주소·차이 수가 목표 상한을 만족해야 함 | 모든 체크포인트에 작은 구조 차원/차이 수가 있다는 증명이 없고, 대수적 재결합의 native 일치도 별도다. |
| 원본 순서를 보존하는 전이 코드 | 항별로 a -> RN32(a+p)를 만들고 함수 합성으로 전체 전이를 표현. 실제로 작고 싸게 구성되는 합성 표현이 있어야 함 | 전 상태 진리표는 유한하지만 크고, 현재 입력에서 항을 만드는 비용이 남는다. 작은 상태 몫을 근거 없이 가정할 수 없다. 아래 분리 정리는 제한된 API에서 이를 확인한다. |

전체 상태 진리표는 함수 하나당 N*32비트, N=4,278,190,080개의 유한 FP32 상태를
취하면 약 15.94 GiB의 단순 표다. 이는 **단순 표 구현의 비용**이지 모든 가능한
전이 함수 표현의 크기 하한이 아니다. 상수 덧셈 함수 자체는 작은 프로그램으로
표현할 수 있다는 점을 혼동하지 않는다. 표의 유한성으로 목표 달성을 주장하지 않는다.

## 3. 대수적 코드만으로 원본 결과가 정해지지는 않는다

참조 연산을 순서대로 RN-even FP32 FMA, 마지막 저장을 RN-even BF16로 고정한다.
가중치를 모두 1로 두면 입력 항의 덧셈이다. 다음 두 순서는 같은 다중집합이며
정확한 실수/정수 합도 모두 1이다.

    (2^24, 1, -2^24)  -> native FP32 0 -> BF16 0
    (2^24, -2^24, 1)  -> native FP32 1 -> BF16 1

따라서 **순열에 불변인 항 요약만** 받은 디코더로는 두 원본 결과를 모두 복원할 수 없다.
순서를 포함한 추가 정보를 사용하거나 원본 입력을 다시 처리하는 다른 알고리즘까지
배제하는 명제가 아니다. Tensor Core의 모든 reduction topology에 대한 명제도 아니다.

함수 f(x)를 위 세 항의 원본 합으로 놓고

    x=(2^24,0,-2^24), y=(0,1,0)

로 두면 f(x+y)=0 이지만 f(x)+f(y)=1이다. 모든 입력 항과 x+y의 항은 BF16에도
정확히 표현된다. 즉 이 반례는 입력 양자화 차이로 만들어진 것이 아니다.

자기정정에 필요한 관계를 일반 함수로 쓰면

    f(x) = f(x+u) - f(u) - Delta_f(x,u)
    Delta_f(x,u) = f(x+u) - f(x) - f(u)

이다. Delta를 0으로 놓는 것은 틀리고, 원래 f(x)를 계산해 Delta를 얻는 것은
순환적이다. 이 식은 **반올림 차이를 공짜로 생성하는 알고리즘이 아니다**.

## 4. 제한된 native 상태의 구성적 분리 정리

### 정확한 범위

유한 FP32 상태, RN-even 덧셈, gradual underflow, 임의의 유한 FP32 덧셈 항,
마지막 RN-even BF16 저장을 허용하는 **독립적인 전이 API**를 다룬다.
특정 HF 모델의 도달 가능한 상태 집합이나 특정 GPU의 FTZ 동작을 가정한 정리가 아니다.

### 정리

서로 다른 두 유한 FP32 비트 상태 a,b는 길이 최대 2인 같은 덧셈 suffix 뒤의
BF16 저장에서 구별할 수 있다. 부호가 다른 두 0은 빈 suffix로 구별한다.

### 구성과 증명

숫자값이 다르면 다음을 선택한다.

    c1 = -a
    d = RN32(b-a)
    c2 = sign(d) * 2^-134

첫 상태의 결과는 RN32(a-a)=+0이다. 모든 유한 FP32 수는 2^-149의 정수배이므로
b-a가 0이 아니면 d도 0이 될 수 없다. overflow면 부호가 있는 무한대이며 역시 0이 아니다.
유한한 경우 |d| >= 2^-149이다.

0에 c2를 더한 값의 크기는 정확히 2^-134이다. BF16의 최소 양의 subnormal은
2^-133이므로 이 값은 0과 최소 subnormal 사이의 정확한 중간점이며 ties-to-even으로
부호가 있는 0에 저장된다.

반면 d와 c2는 같은 부호이다. 유한한 경우 합의 크기는 적어도
2^-134 + 2^-149이고, 이 경계 근방의 FP32 간격은 2^-149이므로 RN32 이후에도
2^-134보다 엄격히 크다. 더 큰 값이나 무한대도 해당 경계로 돌아오지 않는다.
따라서 BF16 저장 결과는 0이 아니다. 두 상태는 구별된다. 부호 있는 두 0은
즉시 BF16로 저장하면 부호 비트가 달라 구별된다. QED.

이 증명은 순서를 지키는 다른 압축/계산 알고리즘의 부재를 증명하지 않는다.
분리용 suffix는 두 상태를 받아 만드는 증명 증인이며, 아직 모르는 LLM 상태를
찾아내는 정보 생성기로 사용할 수 없다.

### 상태 코드에 관한 정확한 귀결

위 API의 모든 상태와 모든 suffix를 보존하고, 상태와 관련된 다른 side information을
받지 않는 고정 길이 상태 코드는 injective여야 한다. 유한 FP32 비트 상태 수는
N=2^32-2^24이므로 m개의 독립 상태를 코드만으로 보존하려면

    B >= ceil(log2(N^m))

이다. m=121이면 3,872비트이다. 따라서 192비트 코드를 **아무 부가 정보도 없는
121개 임의 FP32 중간 상태의 완전한 대체물**로 쓸 수는 없다.

이는 이전의 |오차|<=1 조건부 3진법 복원 정리를 반박하지 않는다. 그 정리는
예측값과 오차 보증을 따로 사용한다. 모든 side information의 비용을 세어야 한다.
또한 고정 W와 입력에서 상태를 다시 계산하는 방법은 이 code-only 가정에 속하지
않는다. 위 정보량 논증은 그 재계산 시간의 하한도 아니다.

**실제 체크포인트의 도달 상태 수, 가중치 압축률, 필요한 가중치 읽기 수, 405B 지연에
관한 하한으로 이 결과를 확대하지 않는다.** 원래부터 BF16 저장이 끝난 실제 경계에서는
이미 사라진 FP32 비트까지 보존할 필요도 없다.

## 5. 최신 자료가 해결한 것과 해결하지 않은 것

2026-09-05 조회. 아래 논문 결과는 로컬에서 재현하지 않았다.

1. Hirahara & Shimizu, *Optimal Random Self-Reductions for All Linear Problems*,
   ECCC TR26-048 revision 1 (2026-04-16), STOC 2026.
   https://eccc.weizmann.ac.il/report/2026/048/
   ECCC 초록과 저자 설명을 확인했다. 유한체 선형 문제를 일정 입력 비율에서
   맞히는 작은 회로가 먼저 주어져야 한다. 결과는 무조건적인 빠른 계산기 생성이
   아니며, 확률적 정확성 및 advice/field 조건도 별도로 읽어야 한다.
2. Hirahara & Shimizu, *Error-Correction of Matrix Multiplication Algorithms over
   Integers*, FOCS 2026 채택 목록 및 저자 초록.
   https://focs.computer.org/2026/accepted-papers/
   https://nobutakashimizu.github.io/mypapers/docs/conference/
   정수 확장과 약한 average-case solver 전제를 확인했다. 이번 조회에서 이 항목의
   전체 원문/세부 상수/완전한 알고리즘을 확보하여 검증한 것은 아니다.
   채택 확인을 전체 증명 검토로 표현하지 않는다.
3. Anand, van den Brand & McCarty, *The Structural Complexity of Matrix-Vector
   Multiplication*, arXiv:2502.21240v3 (2026-02-09).
   https://arxiv.org/html/2502.21240v3
   본문의 Theorem B.9는 pseudodimension d, 열당 서로 다른 값 T를 명시하며
   전처리 약 O(Tmn), query O(T n m^(1-1/d)+m)를 준다. 작은 d/T가 임의 BF16
   체크포인트에 자동으로 보장되거나 native 반올림 일치가 증명되는 것은 아니다.

   arXiv:2606.00279v2 (2026-06-05).
   https://arxiv.org/html/2606.00279v2
   본문의 reduction order, 실제 store, SFU 및 kernel별 실행 경계 설명을 확인했다.
   원본 재현 명세에 참고했으나 해당 GPU emulator나 모델 실험을 여기서 실행하지 않았다.

| 의무 | 이번 상태 |
|---|---|
| O1 임의 체크포인트의 자동 구성 | 목표 예산을 충족하는 구성기 없음. OPEN |
| O2 완전한 인과 실행 | 값싼 전체 native 출력/상태 생성 절차 없음. OPEN |
| O3 원본 출력·RNG·상태 대응 | 위 제한된 덧셈 API의 증명만 있음. 전체 HF/native 대응 OPEN |
| O4 전체 비용의 충분한 상한 | 소형 분리 증인의 상수 길이는 전체 실행 비용 상한이 아님. OPEN |
| O5 405B·8 GiB·4B 지연·TTFT | 미증명, 미측정. OPEN |
| O6 완성 이론의 독립 재검증 | 보조 증명과 코드 재검증만 가능. 완성 이론 자체는 없음. OPEN |

값싼 약한 계산기, 작은 native 전이 표현, 작은 구조 차원의 어느 것도 새로 증명하지
못했다. 따라서 최신 정리와 보조 증명을 이어 붙여 이론 완성으로 승격하지 않는다.
핵심 알고리즘이 없는 상태에서 하드웨어 측정만 남았다고 보고하지 않는다.
