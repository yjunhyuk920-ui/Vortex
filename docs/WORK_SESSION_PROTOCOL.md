# VORTEX Work-Session Protocol

Version: CTC-2026-09-05.

This protocol implements [Constructive Theory Contract](CONSTRUCTIVE_THEORY_CONTRACT.md). It supersedes older 'decide and stop' and mandatory hosted-reexecution wording without weakening evidence preservation or branch protection.

## Start and formulate

Verify remote repository, branch/head SHA, PR state and current committed evidence. Read the startup documents in `../AGENTS.md`, especially current mission/contract, failures, assumptions, state and next action. Historical next-experiment instructions are not automatic authorization.

For core research: freeze the final theorem and O1-O6 ledger; compare three different execution principles; select the strongest credible >=10x route; register hypotheses, exact scope, input/config hashes, success/rejection criteria, numerical/state contract, complete cost terms and cheapest decisive test locally before looking at results. Preserve this preregistration with the final evidence. No pre-experiment remote commit is required.

For an approved governance-only change: edit the contracts and affected entry points; do not manufacture a research trio, experiment number, theorem or benchmark merely to satisfy a template.

## Construct, test, revise

Connect every primary task to an essential obligation. Construct finite subroutines and their proofs/costs, rather than assuming the missing information source. Run the cheapest available decisive validation before large kernels/backends. Register an explicit native/state/scaling link before primary toy work.

Stop a decisively rejected candidate promptly. Within the available session continue another credible principle or a surviving construction's next missing obligation. Do not repeatedly vary a closed family or treat an auxiliary lemma as completion of the final theory.

Use actual local reference/unit/property/adversarial/checkpoint tests and deterministic regeneration where applicable. Retain raw logs, pins, configs, original results, checksums, failures and claim boundaries. Missing GPU/checkpoint/package/network is infrastructure, not scientific rejection. Never imitate target hardware measurements.

## Persist after local validation

```text
LOCAL_RESEARCH -> LOCAL_VALIDATION_PASS -> COMMIT_PUSHED -> REMOTE_COMMIT_VERIFIED
```

Update every affected state/next/decision/assumption/validation/handoff document and README. Research decisions remain in scientific ledgers; policy-only decisions may use a linked governance decision record without rewriting historical scientific results.

Use a descriptive research branch from an observed remote SHA. Do not directly push main, force-push, bypass branch protection or merge unrelated research. Use the connected writer when shell Git is unavailable. Read back branch SHA, commit metadata and changed-file hashes; inspect the PR when applicable.

GitHub Actions is used only when explicitly requested. Do not dispatch duplicate hosted science or wait for it as a scientific completion gate. Existing automatic checks and branch protection still apply; a blocked merge is reported, not bypassed.

## Documentation-only validation

Review changed Markdown, UTF-8/fences, relative-link targets, cross-file status vocabulary, unchanged mission and evidence boundaries, precedence of superseded rules, and preservation of existing evidence. Save the local validation result and content hashes. Full runtime tests and hardware runs are not implied by a documentation check. State the actual validation scope.

## Three endings

A candidate can end as PROMOTE, REVISE, REJECT CORE/RETAIN AUXILIARY, REJECT, or INFRASTRUCTURE FAILURE. These decisions do not by themselves end goal-directed research.

A session can end with partial work because of its actual execution boundary. Record the exact remaining essential obligation, last valid artifacts, next decisive action and unexecuted checks. No infinite-work or background promise, failure suppression, false PASS or relaxed criterion.

The theory ends successfully only at `THEORY_STATUS=VERIFIED_IN_MODEL` under O1-O6. Real target acceptance ends only at `HARDWARE_STATUS=E7_VERIFIED`. `HANDOFF_STATUS=REMOTE_COMMIT_VERIFIED` independently closes repository persistence. A governance-only request can be completed without claiming either scientific achievement.

## Final report

Lead with the delivered algorithm/proof or the actual requested change, obligations closed, full-budget conclusion and decisive remaining gap. Then give commit/branch/PR, exact local checks, remote read-back, README status and any remainder. Identify conditional theory and unmeasured hardware explicitly; test/file/commit counts are supporting evidence, not the main accomplishment.
