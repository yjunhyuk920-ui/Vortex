# Architecture Gate 0 candidate: Cascade Capsule v0

Evidence: **E0 architecture / E1 executable budget calculator**

This document defines one complete model-wide candidate path before a production backend is built. It does not claim that the 405B target is feasible. The candidate advances only if the committed real-model falsification harness measures a repair rate compatible with the budget.

## Hypothesis

For warm decode, normalized activations and attention history occupy bounded effective subspaces that do not grow in proportion to model width or context length. If that remains true on disjoint prompts, a runtime can keep only projected operator images and an active token set on the GPU, while using the original model as a cold repair source.

The candidate combines two independently falsifiable reductions:

1. hidden-axis projection: `x -> V^T x -> (W V)(V^T x)`;
2. token-axis projection: attention over a bounded active token set plus a repair path.

Related external evidence exists for gated activation-subspace inference and cascade token selection, but VORTEX does not treat those papers as proof of this budget:

- Gated Subspace Inference, arXiv:2605.03109;
- Cascade Token Selection, arXiv:2605.03110.

## Full model path

```text
HF safetensors
  -> automatic first-run layer scan
  -> activation-domain bases
  -> projected images M = W V
  -> low-bit capsule + error metadata
  -> GPU-resident warm path

warm token
  -> embedding row fetch/cache
  -> per-layer pre-attention basis projection
  -> projected Q/K/V images
  -> bounded active-token attention
  -> projected O image
  -> residual merge and norm
  -> projected gate/up images
  -> projected down image
  -> residual merge
  -> projected/progressive LM head
  -> token decision

basis/token-set miss
  -> exact layer/tile repair from original weights/KV
  -> optional online capsule expansion
  -> continue with recorded repair traffic
```

## Activation domains

The budget does not assume one basis works for every tensor. Each layer has four domains:

1. pre-attention normalized residual input, shared by Q/K/V;
2. attention output input to O;
3. pre-MLP normalized residual input, shared by gate/up;
4. gated MLP product input to down.

The candidate ranks are currently 64, 48, 64, and 48. The LM-head hidden basis rank is 64. These are rejection targets, not validated ranks.

## Capsule representation

The projected image for a linear map is `M = W V`. The Gate 0 budget assumes:

- basis storage: 8 bits/element;
- projected-image storage: 3 bits/element;
- metadata and correction indexes: 5% of basis plus image bytes;
- exact original weights retained outside GPU memory as a repair source;
- a maximum 0.75 GiB repair tile in device memory.

A production implementation must add progressive correction or another bounded-error mechanism. The current real-model harness uses floating-point capsules so it can isolate the decisive subspace repair rate before low-bit kernel work begins.

## Residual gate

For orthonormal `V`, the relative residual is computed without reconstructing `V V^T x`:

```text
g = V^T x
rho^2 = max(0, ||x||^2 - ||g||^2) / ||x||^2
```

A row uses the projected path when `rho <= epsilon`. Otherwise the corresponding exact weight is invoked. Quality mode may use a nonzero tolerance; exact greedy mode must fall back whenever the declared error certificate cannot prove the token decision.

## Attention and KV path

Dense 405B attention at long context would violate the compute gate even if all linear weights were compressed. The candidate therefore budgets a bounded active set of 256 token positions per layer and a 2-bit compact KV representation. Recent tokens, selected anchors, and repair metadata must fit inside that bound.

This component is not implemented yet. It has its own rejection test: if quality requires active-token growth proportional to context, this candidate fails even when linear projection succeeds.

The stricter derived threshold is:

```text
A >= 246.889 amortized tokens per full-model-equivalent repair
full-model-equivalent repairs/token <= 0.0040504
```

This is the decisive Gate 0 falsification number. The candidate is rejected or revised if disjoint real-model decode traces cannot reach it while preserving the declared quality mode.

## Real-operation falsification

The committed harness:

```bash
python scripts/run_gate0_falsification.py \
  <local-or-hf-model> \
  --build-prompts experiments/gate0_build_prompts.json \
  --eval-prompts experiments/gate0_eval_prompts.json \
  --gate0-budget gate0_budget.json \
  --rank 64 \
  --epsilon 0.05 \
  --max-new-tokens 64 \
  --output gate0_falsification.json
```

The harness:

1. captures bases only from build prompts;
2. generates exact baseline continuations on disjoint evaluation prompts;
3. replaces actual Q/K/V/O and MLP `Linear` modules with `GatedProjectedLinear`;
4. offloads exact matrices to CPU and loads them only on a gate miss;
5. measures token agreement, fast/slow rows, cold bytes, capsule reads, wall-clock, and full-stream-equivalent repairs per token;
6. rejects the candidate when measured `A` is below the certificate threshold.

Hook-only evaluation is not counted as E2. Hooks are used only to build the basis; evaluation executes through the replacement module.

## Promotion and rejection rules

Promote the hidden-axis component only when all are true:

- build and evaluation prompts are disjoint;
- the real operation is replaced during generation;
- token agreement meets the declared mode;
- measured `A >= 246.889` using the same accounting convention;
- rank and capsule growth remain bounded across prompts;
- the result is reproduced on at least three model sizes before extrapolating to 405B.

Reject or revise when any are true:

- hot traffic or compute exceeds the 4B ratio before cold repair;
- weighted repair rate implies `A < 246.889`;
- required rank grows with hidden width toward full rank;
- active attention tokens grow proportionally with context;
- low-bit capsule correction traffic erases the projected savings;
- CUDA wall-clock does not follow the byte/compute model.

## Current boundary

The calculator has passed its local unit tests. No real pretrained model result is committed yet. The 4B baseline values are explicit proxies and must be replaced by same-machine measurements. Therefore the candidate status is **conditional**, not a passed Architecture Gate 0.
