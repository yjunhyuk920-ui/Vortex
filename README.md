# VORTEX

VORTEX is a research runtime for executing very large Hugging Face models under a small GPU-memory budget while preserving the behavior of the original model.

## Non-negotiable target

> Run an arbitrary Hugging Face model—including a 405B-class dense model—on an 8GB VRAM machine with no user-side training, distillation, fine-tuning, calibration workflow, or model-specific manual conversion, while preserving the original model's quality and approaching the wall-clock experience of running a native 4B model on the same machine.

The intended interface is:

```bash
vortex run meta-llama/Llama-3.1-405B-Instruct
```

Graph inspection, shard discovery, runtime-format generation, scheduling, caching, repair, and certification must be automatic. The target is not reduced when an intermediate architecture fails.

## Current evidence level

The repository contains **E1 primitives and falsification infrastructure**. It does not yet contain an E4 405B completion.

Implemented:

- Hugging Face config and safetensors shard discovery without constructing the full model.
- Tensor, slice, and layer loading with byte-bounded caching.
- A streamed tiny-Llama reference decoder and exact Jacobi comparison path.
- Progressive LM-head decision certification.
- `OnlineAtlasLinear` exact-on-span replay with exact cold fallback.
- Real `nn.Linear` replacement experiments on TinyLlama 1.1B.
- Layer, row-tile, 2D residual-tile, adjoint-tile, and block-shared repair experiments.
- Corrected Gate 0 memory, traffic, and compute accounting.
- GitHub Actions experiments and reproducible JSON artifacts.

## Corrected Gate 0 accounting

The source of truth is [`architecture_gate0_budget.json`](architecture_gate0_budget.json), generated by:

```bash
python scripts/run_architecture_gate0.py
```

```text
traffic/token = hot traffic + selected cold bytes / committed block tokens
compute/token = hot compute + selected exact arithmetic for every token
```

Block sharing amortizes storage traffic. It does **not** amortize arithmetic performed with selected exact weights.

405B analytic limits:

```text
peak-state estimate:              4.30497 GiB / 8 GiB
hot traffic:                      1.29249 GiB/token
traffic limit:                    2.83517 GiB/token
hot compute:                      3.53152 GFLOP/token
compute limit:                   12.13274 GFLOP/token
maximum exact repair fraction:    1.01727%
```

The original `VORTEX-WAVE-1` point used 25% exact repair and projected 214.91 GFLOP/token. That design point is rejected.

## Rejected mechanisms

TinyLlama 1.1B evidence rejects these as steady-state paths:

- exact-span Atlas warm decode;
- rank-32 approximate capsule plus exact layer-suffix repair;
- rank-32 approximate capsule plus output-row repair;
- residual-energy-ranked 2D repair applied per token;
- exact-target adjoint 2D repair applied per token;
- the original 25%-repair `VORTEX-WAVE-1` point.

## Surviving logical oracle

The corrected exact-target block-shared oracle found one budget-compatible upper-bound case:

```text
selected exact tiles:               128
selected exact bytes:             8 MiB
repair fraction:                0.19064%
zero-repair exact prefix:             1 token
repaired exact prefix:                2 tokens
incremental exact prefix:             1 token
traffic efficiency E:           1049.09
projected traffic:                2.01494 GiB/token
projected compute:                5.14343 GFLOP/token
```

This is **not E2**. Exact target tokens and teacher-forced gradients chose the tiles; only O/down projections and one evaluation prompt were tested; no sound online commit certificate exists.

Raw provenance and the normalized result are recorded in [`results/tinyllama_1_1b_block_shared_combined_gate.json`](results/tinyllama_1_1b_block_shared_combined_gate.json).

## Active engineering gate

The active experiment removes the oracle inputs:

```bash
python scripts/run_block_shared_residual_selector.py \
  --model TinyLlama/TinyLlama-1.1B-Chat-v1.0 \
  --device cpu \
  --block-tokens 64
```

The selector may use only:

- approximate autoregressive activation residuals;
- precomputed weight-tile norms.

It may not use exact target tokens, target logit margins, or teacher gradients. Exact output is used only afterward to measure the causal-prefix result.

Advancement still requires:

1. repair increases the exact prefix beyond the zero-repair baseline;
2. traffic and compute gates both pass;
3. the result repeats across disjoint prompt families and seeds;
4. a sound runtime commit certificate is implemented;
5. all relevant model operations are covered;
6. physical bytes, VRAM, and wall-clock are measured.
